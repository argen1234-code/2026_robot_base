# 无线 DAP 实测记录（2026-11-02）

## 结论与范围

Horco 无线 DAP（序列号 `d9381b44`）在最终现场通过现有 EXE 的完整固件匹配、4 次重连、持续采样及两台电机独立低速正反转验证。最终保持连接，两台电机全部失能，并恢复测试前参数。

原始错误 `SWD/JTAG communication failure (Unexpected ACK '0')` 在初期曾复现，最终验证阶段没有再次出现。本次无线排查未修改连接或固件控制代码；没有屏蔽 ACK 错误、跳过 Flash 校验或自动重发运动命令。根因仍未确认，不能宣称已永久修复。中途用户更换过调试器，最终测试明确指定上述无线 DAP；设备列表中的旧记录不能代替实际会话身份。

## 验证方法

- 通过生产上位机 HTTP API 调用连接、准备、使能、运行、停止与全部失能，路径与网页相同。
- 完整比较板上 60,268 字节 Flash 加载段与当前 AXF；每次连接保留原有一致性校验。
- 连续 4 次断开、重连并检查递增的系统心跳。
- 持续采样 75 秒，共 347 次状态查询，无连接中断；观察到的最大采样年龄 87 ms。采样年龄不是端到端控制延迟。
- 用户确认车轮架空后，逐台测试 ±0.5 rad/s。检查 `executed_seq/result`、在线状态、反馈时效、故障位与速度反馈；测试时速度上限 2 rad/s、电流上限 1 A、加速度 2 rad/s²。

每阶段取后半段反馈均值，预先设置容差 ±0.15 rad/s。

这证明当时的无线独立控制链路工作，不代表 WASD 实车方向、带载、高速、无线抗干扰或断线自停验收。既有 `wasd_validation.json` 中 WASD 专项的 `physical_motion_tested=false` 保持原意。

## 已排查但未确认为根因

初期读取探针和芯片 ID 成功，后续内存访问仍可能 ACK 失败，或者返回成功但个别数据字错误。同一地址重读又正常；暂停 CPU 时完整校验通过，恢复运行后错误再次出现。不同 SWD 时钟、常规传输参数及 USB 接口未得到稳定修复。

最终现场 `DBGMCU_CR=0x00670007`。暂时去掉 D1/D3 调试时钟位后及恢复后，运行中的 Flash 比较都通过，因此没有加入未经证实的调试时钟补丁，原值已恢复。不能仅凭“暂停时正常”就判定具体硬件或代码模块故障。
