# 多功能小车工程操作指南

> 适用工程：STM32H743 + FreeRTOS + LVGL 多功能小车
>
> 文档日期：2026-07-20
>
> 说明：本文依据当前工程代码整理，重点覆盖蓝牙遥控、纯 GPS、GPS+ROS、航点采集、磁力计初始化和 Keil 调试。

## 1. 工程功能概览

当前工程支持以下运行模式：

| 模式值 | 模式名称 | 主要用途 | 关键输入 |
|---:|---|---|---|
| 0 | IDLE | 待机和安全停车 | 无 |
| 1 | 纯 GPS | 根据已采集航点进行室外全向导航 | GPS + QMC5883 |
| 2 | GPS+ROS | GPS 航点导航与 Jetson/ROS 速度指令融合 | GPS + QMC5883 + USB |
| 3 | 微信遥控 | 接收 Jetson 转发的微信遥控数据 | USB |
| 4 | ROS 室内模式 | 室内 ROS 控制 | USB |
| 5 | 蓝牙模式 | 蓝牙方向遥控、模式切换和航点管理 | USART1 蓝牙 |
| 6 | 语音模式 | 语音控制 | 语音模块 |

### 1.1 使用前准备

- 确认电机、电调或驱动板、编码器和底盘供电连接正常。
- 确认 GPS 串口持续收到有效 GGA 数据。
- 确认 QMC5883 安装方向固定，且校准时小车周围没有强磁干扰。
- 蓝牙模块使用 USART1，串口参数为 `9600, 8N1`。
- 使用 GPS+ROS 时，确认 Jetson 与主控 USB 通信正常。
- 第一次实车测试应架空车轮或在空旷区域低风险测试。

## 2. 上电与启动流程

1. 检查机械结构、轮子、电池和线束。
2. 给主控、传感器和电机系统上电。
3. 等待 FreeRTOS、LVGL、GPS、蓝牙和底盘任务启动。
4. 在 Keil Watch 中确认 GPS 数据是否持续刷新。
5. 根据需要采集 GPS 航点。
6. 进入纯 GPS 或 GPS+ROS 模式。
7. 首次进入需要磁力计的模式时，等待磁力计完成约 30 秒初始化和校准。

> **重要：** QMC5883 上电时默认不初始化。首次进入纯 GPS或 GPS+ROS 模式时才初始化一次；本次上电后再次进入相关模式不会重复校准。

## 3. 蓝牙通信协议

### 3.1 串口参数

| 项目 | 参数 |
|---|---|
| 外设 | USART1 |
| 波特率 | 9600 |
| 数据位 | 8 |
| 停止位 | 1 |
| 校验位 | 无 |
| 完整帧格式 | `@payload\r\n` |
| 指令识别应答 | `ok\r\n` |

例如，切换纯 GPS 模式应发送：

```text
@gps\r\n
```

实际字节必须以回车、换行结束，即十六进制结尾为 `0D 0A`。

> 蓝牙返回 `ok` 仅表示指令字符串已被识别，不一定代表 GPS 航点已经采集成功。采点结果还应查看 `g_chassis_gps_route_last_result_debug`。

### 3.2 模式与航点指令

| 功能 | 推荐指令 | 可用别名 | 说明 |
|---|---|---|---|
| 清空 GPS 航点 | `@gps_clear\r\n` | 无 | 清除 RAM 中的全部航点 |
| 采集当前位置 | `@gps_add\r\n` | `@gps_point\r\n`、`@gps_sample\r\n` | 将当前有效 GPS 坐标加入航点数组 |
| 远程追加坐标 | `@remote_add\r\n` | 无 | 下一帧接收严格的 `@lat,lon\r\n` 坐标并追加到现有航点末尾 |
| 进入纯 GPS | `@gps\r\n` | `@g\r\n` | 启动纯 GPS 航点导航 |
| 进入蓝牙/室内模式 | `@i\r\n` | `@indoor\r\n`、`@bt\r\n`、`@bluetooth\r\n` | 进入蓝牙遥控模式 |
| 最高优先级无力 | `@!\r\n` | 无 | 锁存无力状态，PWM清零且TB6612方向输入置低，所有其他蓝牙控制返回`error` |
| 解除无力锁存 | `@~\r\n` | `@resume\r\n`、`@power_on\r\n` | 只解除锁存并保持停车，必须重新发送模式或运动指令 |

当前没有单独的“蓝牙命令直接强制进入 GPS+ROS”字符串。GPS+ROS 模式由有效的 Jetson USB 模式 1 数据触发；当小车处于纯 GPS 模式且检测到有效的 Jetson 模式 1 数据后，会自动升级为 GPS+ROS。

`@!\r\n` 的优先级高于 GUI、普通蓝牙模式、语音和 Jetson。该状态为锁存状态，不会因蓝牙超时或收到 Jetson 数据自动解除；磁力计校准转动期间同样会强制无力。

### 3.3 蓝牙运动指令

| 动作 | 短指令 | 长指令/别名 |
|---|---|---|
| 前进 | `f` | `forward` |
| 后退 | `b` | `back`、`backward` |
| 左移 | `l` | `left` |
| 右移 | `r` | `right` |
| 原地左转 | `q` | `ccw`、`turn_left`、`rotate_left` |
| 原地右转 | `e` | `cw`、`turn_right`、`rotate_right` |
| 停止 | `s` | `stop` |

发送时仍需使用完整帧，例如：

```text
@f\r\n
@rotate_left\r\n
@stop\r\n
```

运动指令采用状态位切换逻辑：重复发送同一方向可能取消该方向；`stop` 会直接清除运动状态。蓝牙平移和旋转基础速度均为 `60`。

### 3.4 路面识别与显示

LVGL 路面状态现在读取 NanoEdge 路面分类 BSP 的有效结果：

- `indoors` → 室内地面
- `cement` → 水泥路
- `asphalt` → 柏油路

模型尚未初始化、正在收集 32 帧 IMU 窗口、IMU 数据中断或分类错误时显示“未开始识别”。微信/Jetson 的 `indoor`、`outdoor` 场景帧仍会被串口协议解析，但暂不再覆盖 LVGL 路面显示。

以下旧蓝牙指令和隐藏按钮仍可手动切换共享显示，下一次模型产生新分类结果时由模型重新接管：

- `@road_asphalt\r\n`
- `@road_indoor\r\n`
- `@road_cement\r\n`
- `@road_marble\r\n`

## 4. GPS 航点采集与纯 GPS 导航

### 4.1 航点数组特性

- SD 卡是航点主存储，文件路径为 `0:/GPS/GPSPTS.CSV`；文件管理器中对应 `S:/GPS/GPSPTS.CSV`。
- 上电后优先从 SD 卡 CSV 恢复航点；文件不存在或读取失败时使用内部 Flash 双槽备份。
- 首次升级后，如果 SD 卡没有航点文件但 Flash 中已有航点，系统会自动生成 CSV 文件。
- `gps_add`、`remote_add` 会先写临时文件、同步并回读校验，再替换正式 CSV，同时更新 Flash 备份。
- `gps_clear` 会删除 SD 卡中的 `GPSPTS.CSV` 和残留临时文件，并把 Flash 备份更新为空路线。
- 最多保存 10 个航点。
- 采点需要有效且较新的 GGA 定位数据。
- GPS 数据允许的最大年龄为 3 秒。
- 到达航点的判断距离为 2 米。
- 多航点巡航到点后停留 5 秒，再前往下一点。
- 只有 1 个航点时，小车到点后结束导航。
- 至少需要 2 个航点，才能在航点数组之间循环巡航。

### 4.2 推荐采点流程

1. 将小车放到第一个目标位置，等待 GPS 定位稳定。
2. 发送 `@gps_clear\r\n` 清除旧航点。
3. 发送 `@gps_add\r\n` 采集第一个点。
4. 将小车依次移动到其他目标位置，每个位置等待数据稳定后发送一次 `@gps_add\r\n`。
5. 在 Keil Watch 中确认 `g_chassis_gps_route_count_debug` 等于预期航点数。
6. 把小车放到准备出发的位置，确保路线周围安全。
7. 发送 `@gps\r\n` 进入纯 GPS 模式。
8. 首次进入时等待约 30 秒磁力计校准完成，然后观察小车开始导航。

### 4.3 蓝牙远程追加坐标

先发送：

```text
@remote_add\r\n
```

收到 `ok\r\n` 后，下一帧必须发送一个坐标，例如：

```text
@30.12345678,120.12345678\r\n
```

- 纬度和经度都必须包含小数点，并且小数部分至少 8 位。
- 不允许空格、科学计数法、多余逗号或其他字符。
- 纬度范围为 `-90`～`90`，经度范围为 `-180`～`180`。
- 有效坐标追加到当前航点数组末尾，保存到 SD 卡并同步更新 Flash 备份，返回 `ok\r\n`。
- 格式错误、范围错误或航点数组已满时返回 `error\r\n`。
- 无论坐标有效还是无效，处理一帧后都会退出远程追加状态；继续添加必须重新发送 `@remote_add\r\n`。

### 4.4 航点采集结果

变量 `g_chassis_gps_route_last_result_debug` 的含义如下：

| 数值 | 枚举含义 | 说明 |
|---:|---|---|
| 0 | NONE | 暂无结果 |
| 1 | POINT_ADDED | 航点添加成功 |
| 2 | CLEARED | 航点数组已清空 |
| 3 | INVALID_FIX | GPS 无效或数据过旧，采点失败 |
| 4 | FULL | 航点数组已满 |

### 4.5 SD 卡航点文件与文本浏览

文件管理页面标题会显示 `FatFs`。进入 `GPS` 目录并点击 `GPSPTS.CSV`，可以在只读文本页面浏览航点编号、经纬度和 CRC32 校验值。

当前 FatFs 使用 8.3 短文件名，因此航点目录和文件名固定为：

```text
S:/GPS/GPSPTS.CSV
```

CSV 使用 `GPS_ROUTE_V1` 格式，经纬度保存 10 位小数。不要在小车运行时从外部设备修改 SD 卡；如需人工编辑，必须同步生成正确 CRC32，否则系统会判定文件无效并回退到 Flash 备份。

文件管理器还支持浏览启动时加载到 SDRAM 的五个原始 `.bin` 图片：

- `icon.bin`
- `bg.bin`
- `data.bin`
- `setbtn.bin`
- `lock.bin`

在 450 ms 内连续点击同一个 `.bin` 文件两次即可打开。图片会保持宽高比自动缩放并居中显示；在图片区域向任意方向滑动即可退出，也可以点击右上角“返回”。其他没有预设宽高和颜色格式的 `.bin` 文件不会作为图片打开。

### 4.4 纯 GPS 的速度与停车行为

纯 GPS 模式保留原有导航死区处理：

- 最小平移速度 `Min_speed = 60`，用于克服底盘低速死区。
- 导航输出需要运动时可直接达到最低有效速度，不经过新增的斜坡平滑。
- 到达航点后立即将目标速度清零，不做停车减速过渡。
- 多航点模式下停车等待 5 秒后再前往下一航点。

因此，纯 GPS 到点停车应表现得比较干净利索；GPS+ROS 的速度变化则保留平滑处理。

## 5. 磁力计初始化与校准

### 5.1 当前初始化策略

- QMC5883 上电默认不初始化。
- 首次进入纯 GPS 或 GPS+ROS 模式时执行一次初始化和校准。
- 校准过程约持续 30 秒。
- 校准期间底盘会旋转，请确保周围空间足够。
- 同一次上电周期内，后续再次进入需要磁力计的模式不会重复校准。
- 重新上电或复位后，首次进入相关模式仍会重新校准。

### 5.2 调试判断

在 Keil Watch 中观察：

```text
g_chassis_mag_initialized_debug
```

- `0`：尚未完成磁力计初始化。
- `1`：本次上电的磁力计初始化和校准已经完成。

首次发送 GPS 模式指令后，底盘任务会同步执行校准，因此蓝牙 ACK 或模式响应可能延后约 30 秒。上电后、首次进入 GPS 前，QMC5883 调试数据保持为零属于当前设计的正常现象。

## 6. GPS+ROS 模式

### 6.1 进入方法

1. 先按第 4 节采集至少一个有效 GPS 航点。
2. 发送 `@gps\r\n`，让小车进入纯 GPS 模式。
3. Jetson 通过 USB 周期发送模式值为 `1` 的有效二进制数据帧。
4. 主控检测到 Jetson 在线、模式为 1 且 GPS 可用后，自动进入 GPS+ROS 模式。

也可以在小车控制逻辑允许的情况下，直接让 Jetson 持续发送模式 1 帧；是否能成功进入仍取决于 GPS、航点、磁力计和模式可用条件。

### 6.2 USB 数据帧

GPS+ROS 使用 12 字节二进制帧：

```text
AA 55 mode vx[4] vz[4] checksum
```

| 字节 | 内容 | 说明 |
|---:|---|---|
| 0 | `0xAA` | 帧头 1 |
| 1 | `0x55` | 帧头 2 |
| 2 | `mode` | `1` 表示 GPS+ROS |
| 3～6 | `vx` | IEEE-754 `float`，小端序 |
| 7～10 | `vz` | IEEE-754 `float`，小端序 |
| 11 | `checksum` | 第 2～10 字节逐字节 XOR |

零速度、模式 1 示例：

```text
AA 55 01 00 00 00 00 00 00 00 00 01
```

Jetson 在线超时为 500 ms，建议以明显短于 500 ms 的周期持续发送，例如 50～100 ms 一帧。

### 6.3 GPS相对角与ROS坐标系转换

STM32发送的 `heading_to_target_deg` 是车体相对目标角：`0°=前方`、`90°=右侧`、`180°=后方`、`270°=左侧`，顺时针为正。ROS地图坐标的yaw以逆时针为正，因此Jetson生成虚拟目标时必须使用：

```text
goal_yaw_ros = robot_yaw_ros - heading_to_target_cw
```

修正后，STM32的右侧 `90°` 会转换为ROS的 `-90°`，左侧 `270°` 会转换为ROS的 `+90°`。该转换只用于GPS虚拟目标发布，不改变已经正常工作的室内Nav2坐标系。

### 6.4 平滑控制

GPS+ROS 模式保留速度平滑处理，避免模式切换或 ROS 指令变化时速度突变：

- 平移速度变化率：每秒 300 个内部速度单位。
- 旋转速度变化率：每秒 200 个内部速度单位。
- 纯 GPS 模式绕过该平滑逻辑。
- IDLE 或模式不可用触发的安全停车会立即清 PWM，不等待平滑减速。

| `g_chassis_powerless_debug` | 蓝牙最高优先级无力锁存是否生效 |

### 7.1 GPS 导航重点字段

展开 `g_gps_debug.navigation`，重点检查：

- `is_navigating`：是否处于导航状态。
- `total_waypoints`：已经加载的航点总数。
- `current_waypoint_index`：当前目标点索引。
- `current_latitude_deg`、`current_longitude_deg`：当前坐标。
- `target_latitude_deg`、`target_longitude_deg`：目标坐标。
- `distance_to_target_m`：与目标点距离误差，单位米。
- `target_bearing_deg`：当前位置指向目标点的方位角。
- `current_heading_deg`：当前磁力计航向。
- `heading_error_deg`：目标方位与当前航向的误差。
- `command_vx`、`command_vy`、`command_wz`：导航计算得到的速度指令。
- `phase`：运行或到点停留阶段。
- `navigation_mode`：纯 GPS 或 GPS+ROS 导航调试标记。

## 8. 常见问题排查

### 8.1 GPS 数据持续刷新，但小车不走

按以下顺序检查：

1. `g_chassis_gps_route_count_debug` 是否大于 0。
2. `g_gps_debug.navigation.total_waypoints` 是否大于 0。
3. `g_gps_debug.navigation.is_navigating` 是否为 1。
4. GPS GGA 的定位质量 `qf` 是否至少为 1。
5. 当前纬度是否有效，GPS 数据是否超过 3 秒未更新。
6. `g_chassis_mag_initialized_debug` 是否已经变为 1。
7. `distance_to_target_m` 是否已经小于 2 米；若小于 2 米，系统会认为已经到点。
8. `command_vx/vy/wz` 或 `Vx_set/Vy_set/Wz_set` 是否非零。
9. 电机目标值、PWM、使能脚和底盘供电是否正常。

### 8.2 航点数量一直为 0

- 确认发送的是完整帧 `@gps_add\r\n`。
- 查看 `g_bt_debug.last_payload` 是否正确收到 `gps_add`。
- 查看 `g_chassis_gps_route_last_result_debug`。
- 结果为 3 时，说明 GGA 定位无效或数据超过 3 秒。
- 蓝牙 `ok` 不等于航点必然添加成功。

### 8.3 蓝牙没有返回 `ok`

- 确认串口为 USART1、9600、8N1。
- 确认帧以 `@` 开始，以 `\r\n` 结束。
- 查看 `g_bt_debug.rx_event_count` 是否增加。
- 查看 `g_bt_debug.complete_frame_count` 和 `format_error_count`。
- 首次进入 GPS 时，ACK 可能被同步磁力计校准延迟约 30 秒。

### 8.4 无法进入 GPS+ROS

- 确认 Jetson 发送的是 12 字节二进制数据，而不是十六进制字符文本。
- 确认帧头为 `AA 55`，模式值为 1。
- 确认 `vx`、`vz` 使用小端 `float`。
- 重新计算第 2～10 字节 XOR 校验。
- 发送周期必须短于 500 ms 超时。
- 确认 GPS 有效、航点已加载、磁力计已经初始化。
- 先进入纯 GPS，再观察是否自动升级到 GPS+ROS。

### 8.5 电机目标非零，但轮子不转

- 检查电机驱动供电、急停、使能和共地。
- 检查 PWM 是否实际输出。
- 检查电机方向配置和 CAN/串口电机通信。
- 检查底盘是否仍处于 IDLE 或安全停止状态。
- 检查机械卡滞和负载是否过大。
- 蓝牙基础速度和纯 GPS 最低速度均为 60；若仍无法启动，应优先排查硬件与底层电机闭环。

### 8.6 上电后 QMC5883 数据一直为 0

这是当前延迟初始化策略的正常表现。首次进入纯 GPS 或 GPS+ROS 后才会初始化和校准；完成后检查 `g_chassis_mag_initialized_debug` 和 `g_qmc5883_debug`。

## 9. 当前版本注意事项

1. GPS 和 Jetson 在线时间戳可能由已缓存的有效数据刷新，因此物理断线不一定能被准确识别。
2. 蓝牙 `ok` 只代表指令字符串被识别，不代表 GPS 采点一定成功。
3. 蓝牙动作请求只有一个待处理槽位，连续快速发送不同指令时，前一个请求可能被后一个覆盖。
4. 首次 GPS 模式的磁力计校准会同步占用底盘任务约 30 秒。
5. 航点没有写入 Flash，复位或掉电后必须重新采集。
6. GPS 室外定位存在误差，2 米到点阈值并不代表实际机械位置能达到厘米级精度。

## 10. 安全操作清单

### 上电前

- [ ] 电池电压和极性正确。
- [ ] 轮子、联轴器和电机固定可靠。
- [ ] GPS 天线朝上且无遮挡。
- [ ] 磁力计远离大电流线束、磁铁和铁磁材料。
- [ ] 急停或断电手段可随时操作。

### 采点前

- [ ] GPS 已获得有效定位。
- [ ] 坐标数据稳定刷新。
- [ ] 已清除不需要的旧航点。
- [ ] 每次采点后确认结果为 1。
- [ ] 航点之间不存在台阶、墙体、车辆或人员通道等风险。

### 启动导航前

- [ ] `g_chassis_gps_route_count_debug` 符合预期。
- [ ] 至少两个点用于循环巡航。
- [ ] 校准旋转区域安全。
- [ ] 小车周围留有足够制动和转向空间。
- [ ] 操作人员能够立即发送 `@stop\r\n` 或切断电机动力。

## 11. 快速指令卡

```text
# 清空航点
@gps_clear\r\n

# 采集当前点，可重复执行，最多 10 个
@gps_add\r\n

# 进入纯 GPS
@gps\r\n

# 返回蓝牙遥控模式
@bt\r\n

# 蓝牙运动
@f\r\n       # 前进
@b\r\n       # 后退
@l\r\n       # 左移
@r\r\n       # 右移
@q\r\n       # 原地左转
@e\r\n       # 原地右转
@stop\r\n    # 停止
```

推荐的 GPS 循环巡航操作顺序：

```text
@gps_clear\r\n
@gps_add\r\n       # 在航点 1
@gps_add\r\n       # 在航点 2
@gps_add\r\n       # 可选：航点 3
@gps\r\n           # 启动导航
```
