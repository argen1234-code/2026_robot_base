## 硬件路径与连接

**PC USB → 现有 Horco CMSIS-DAP / ST-Link → SWD → STM32H743 → 现有 CAN 收发器 → RS05。**

复用 `RobStride05_H743_HAL/App/app_debug.h` 中的 `g_debug`。当前固件没有 UART/USB CDC 上位机协议，因此这里不使用 COM5。本次已更新并下载匹配固件，增加参数兼容诊断。

1. 使用当前已经下载、能正常运行的固件。在 Keil 内确认 CPU 为 Run，然后退出 Debug，释放调试器。不得同时用 Keil Watch 修改命令区。
2. 启动上位机，刷新并选择调试器，点击连接。
3. 后台从工程 AXF 的 DWARF 自动解析变量地址与字段布局，核对板上完整 Flash 加载段；不一致则拒绝连接。不会复位、烧录、暂停或自动启动 CPU。当前同时支持两个工程：`RobStride05_H743`（FreeRTOS 版）与 `RobStride05_H743_HAL`（单线程版），启动时列出附近所有候选 AXF（新的在前），连接时按板上 Flash 自动选中并做整段比对；日志会显示 `Flash 一致 · 工程名`。也可用 `--axf` 指定唯一 AXF。
4. H743 已连接与电机在线是两个状态。只有新鲜且一致的电机反馈才能显示有效测量；CAN TX ACK 不等于电机在线。

若修改了固件，请重新编译并使用与板上固件匹配的 AXF。源码会自动读取相邻工程的当前 AXF。打包版在本目录结构下也优先读取相邻工程；独立移动后则使用打包时生成的 `firmware_profile.json`，需要重新打包才能更新。

## 控制顺序

当前工程只实现**速度控制**。位置和力矩显示为反馈，不提供位置模式、力矩模式、设零或持久参数写入。

1. 选择探针并连接。自动完成双电机身份核对、速度模式参数配置和零速使能，无需确认框或手动准备/使能。
2. 默认速度上限 33 rad/s、相电流 2.4 A、加速度 20 rad/s²。需要修改时，断开后分别选择两张电机卡片填写限制，再连接应用。
3. 等待“双电机已就绪”，随后直接指定绝对角度、双轮速度、进入 WASD，或选择单电机点击“开始运行”。连接阶段始终下发零目标，不执行编辑框中的运动目标。
4. 单电机 RUN 持续有效，修改后点击“应用新速度”。减速停止保持使能；选中电机失能、全部失能和 Esc 保留。失能或清错后重新连接可恢复就绪。
5. 停止或失能会取消尚在进行的自动配置，同一连接中不会自行重新使能。连接失败在状态和日志中显示原因。

## 参数兼容与本次修复

速度范围依据 RS05 使用说明书 261009 第 37 页：当前采用的速度模式 `spd_ref 0x700A` 明示 `−33～+33 rad/s`。第 6 页标注的 480 rpm±10% 是额定 48 V 下的空载规格，第 32～33 页的 ±50 rad/s 是运控/反馈的编码量程；软件采用当前控制模式明确给出的指令上界。实际达到的速度还取决于母线电压、负载和所设相电流。官方 SampleProgram 的速度控制流程为模式 2 → 使能 → 设置 0x7018/0x7022 → 写 0x700A，但其 RS01 的 44 rad/s 量程不适用于 RS05。

实板电机版本返回 0x00050003。旧版本上位机将电机明确拒绝 0x7022（加速度）和 0x7028（通信超时）统一报为「参数读回不符/超时」，导致准备失败。新版在明确拒绝时尝试手册旧地址 0x201E / 0x200C；本电机也拒绝这些地址，因此采用明确标注的兼容状态。加速度由 H743 已有 20 ms 速度斜坡执行，界面不再虚报电机侧 250 ms 超时。兼容状态直接显示在诊断中，不再要求单独勾选。模式、零速、电流限制仍严格读回核对；回复丢失、数值不符仍报错。

诊断页新增具体参数索引、期望值、实际值、拒绝/不符/超时原因及兼容能力。连接频率改为已实测的 SWD 1 MHz；连接异常会释放会话，需显式重连。释放 SWD 会话本身不会撤销 H743 中已下发的速度。

## 数据与保护

- 目标/斜坡后目标、实际速度、位置、力矩、温度、Iq、电压，最近 30 秒曲线，可切换观测项。显示暂停只冻结曲线，后台仍采集和执行固件保护。
- CSV 导出最近最多 36000 个一致快照，包含时间、MCU tick、online、状态、目标与实测值、电流/电压年龄。离线时原始保留值供排查，分析时必须过滤 `online=0`，并检查 `current_age_ms`、`voltage_age_ms`。
- `MotorStatus` 的连续控制/测量区（当前 148 字节，含命令回执、状态、反馈、限制、健康位和发布时间）使用固件发布序号校验，读前后的序号必须相同且为偶数。遥测每 20 ms 发布一次，电机控制与保护仍每个服务周期执行，避免 USB 读取跨越 1 ms 发布周期而反复失败。后台按 MCU 时间补偿发布到读取结束的年龄，再加上 HTTP 快照年龄使数据失效。偶尔获取失败时保留上次一致快照；运动命令重新获取一致快照，失败则拒绝。CAN 计数、身份信息、OLED、系统与命令区是独立采样，不承诺整组原子快照；控制校验不依赖这些独立诊断字段。
- 普通控制写入对应 `g_debug.cmd` 或 `cmd2`，首次配置写 `setup` 的主机字段，全停写 `stop_all_seq`；，遵守“奇数 → 完整参数 → 读回核对 → 新偶数最后提交”。界面提交成功只表示写入完成；日志会继续等待 `executed_seq/result`，不会把请求当作电机动作完成。
- 页面轮询仅用于显示数据，不控制运行授权。主动点击断开或退出会先请求失能再释放探针，断开后无法继续确认物理状态。
- 若本地服务被强制关闭或 USB/探针突然断开，H743 中的速度指令仍可能持续有效，需重新连接后停止或直接断电。**本次实测该电机拒绝 0x7028 / 0x200C，未验证电机侧 CAN 断线自停；CAN 线断开或 MCU 停止运行时不能承诺自动停机，必须保留可直接切断电源的手段。**
- 本地服务仅绑定 `127.0.0.1`，写 API 校验 Host、Origin 和随机会话令牌，拒绝普通跨站请求。不要将服务转发到公网。
