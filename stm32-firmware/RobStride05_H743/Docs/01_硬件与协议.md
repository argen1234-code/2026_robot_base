## 核实结果

| 项目 | 结论 | 证据与边界 |
|---|---|---|
| MCU | STM32H743IIT6，LQFP176、2 MB Flash | 用户明确确认，`.ioc` 与 Keil 使用该型号。商家目录名不作为型号证据 |
| 晶振、供电 | HSE 25 MHz，板上 5 V 转 3.3 V；软件配置 LDO | 商家原理图和 LED 例程、同板小车工程相互参考。新工程不配置 LSE/RTC |

| CAN 收发器 | 照片芯片顶标 VP230，对应 TI SN65HVD230D，3.3 V | TI 数据手册的器件标识表；照片不能证明器件真伪或跳帽实际连通 |
| OLED | 软件基线 SSD1306、128×64、0x3C（7 位） | 来自用户指定 F407 OLED 源码与初始化序列；实物屏型号尚无独立证据，按用户要求先采用此配置 |
| RS05 协议 | 已核实官方 RS05 CAN2.0 手册 261009 | RS05 同时存在单独的 CAN-FD 文档。用户电机具体版型/固件、当前 ID 未知，不声称已匹配实物 |
| 电机 ID | 0x7F（官方示例默认值），主机 ID 0xFD | 集中在 `App/app_config.h`，只改 MCU 侧地址，不发电机改 ID 指令；2026-10-22 实机反馈以 0x7F 在线 |

读取了同板小车工程的实际分层、RCC、LDO、缓存初始化与引脚配置；没有复制其 LVGL、SDRAM、文件系统或底盘功能。该参考工程及商家 LED 例程中有开启 DCache 的代码，新工程未沿用：**I-Cache 与 D-Cache 都不开启，源码里没有 Cache 使能、关闭、clean 或 invalidate 调用**，`SCB->CCR` 只作只读记录（见 `Docs/07_RTOS移植与上板验收.md`）。

断电接线。用板上引脚名定位，勿把收发器 TX/RX 当 UART 交叉接。

| 开发板/连接端 | 连接对象 | 含义 |
|---|---|---|
| PB9，AF9 FDCAN1_TX | CAN 模块 TX | MCU 输出 → SN65HVD230 D（芯片 1 脚） |
| PB8，AF9 FDCAN1_RX | CAN 模块 RX | MCU 输入 ← SN65HVD230 R（芯片 4 脚） |
| 3.3 V | CAN 模块 3.3V | 收发器电源；该模块不要按 5 V 收发器接法供电 |
| GND | CAN 模块 GND、电机信号地 | 此模块不隔离，短距离共地，CAN 线采用双绞线 |
| CAN 模块 CANH | 电机 CAN_H | 高对高 |
| CAN 模块 CANL | 电机 CAN_L | 低对低 |
| PB10，AF4 I2C2_SCL | OLED SCL/SCK | SCL；不是 SPI 时钟配置 |
| PB11，AF4 I2C2_SDA | OLED SDA | 开漏数据线 |
| 3.3 V、GND | OLED VCC、GND | 按普通支持 3.3 V 的 SSD1306 四针模块使用；I²C 上拉到 3.3 V，若模块不支持须改供电方案 |
| 板卡规定的 5 V 输入 | 开发板电源 | 由板上稳压得到 3.3 V；避免多个供电端互相反灌 |
| 独立直流电源正负极 | 电机主电源正负极 | 官方额定 48 V，最大 60 V；实际电源电压与限流须在首次上电前核对 |
| PA13 / PA14 / NRST / GND / 3.3V 参考 | 调试器 SWDIO / SWCLK / NRST / GND / VTref | 调试器应检测 3.3 V 目标电平；VTref 不等于强制给板供电 |

修正记录：用户确认实物 PB6 不在可接排针内，旧 OLED 接线作废。商家 SILK2.pdf 实际标注 H750XB，与用户板卡版本不一致，撤销此前引用的排针针号。OLED 改用 PB10/PB11（I²C2），这对引脚是否实际引出等待用户核对。下载座 7 针标注：1=RST、2=JTCK/PA14、3=JTMS/PA13、4=GND、5=PA9、6=PA10、7=3.3V2。由于资料封装差异，**实际优先核对板上丝印**。PA9/10 不用于 SWD。没有选 PD0/PD1，是因为商家板资料中它们连接 SDRAM。

照片里的 `120R` 与黄色跳帽通常用于接入模块端 120 Ω 终端。两节点短总线按物理两端各一只 120 Ω；电机端若自带终端，不再叠加第三只。无需把跳帽当软件设置：照片无法确认电机内是否已有终端。通信有问题时，断电测 CANH–CANL 约 60 Ω 可作为两端各 120 Ω 的排查线索；不要带电测阻。

## RS05 基线：不沿用 RS01 量程

速度模式 `run_mode=2` 适合第一轮联调：目标速度单位明确，可同时限制电流、加速度，并直接比较速度反馈；不需要设机械零点，也不建立位置闭环命令。

经典 CAN 1 Mbps，扩展 29 位 ID，DLC=8，无 BRS。STM32 使用 `HAL_FDCAN_*`，不是 F103 的 `HAL_CAN_*`。FDCAN 内核 80 MHz，分频 4，Seg1=15、Seg2=4、SJW=4，总 20 tq、采样点 80%。自动重发关闭，使失败与挂起发送有界可见。

发送 ID = `(type << 24) | (host_id << 8) | motor_id`。反馈的电机 ID 位于 bit8..15，主机 ID 位于 bit0..7；硬件按这 16 位过滤，软件进一步检查帧格式、DLC、类型。反馈 bit16..21 是故障摘要，bit22..23 为 Reset=0、Cali=1、Motor=2。

| 数据/参数 | 地址/报文 | 单位与编码 |
|---|---|---|
| 位置反馈 | 类型 2/24，byte0..1 | 大端 uint16 映射 ±12.57 rad |
| 速度反馈 | byte2..3 | 大端 uint16 映射 ±50 rad/s |
| 力矩反馈 | byte4..5 | 大端 uint16 映射 ±5.5 N·m；不是电流 |
| 温度反馈 | byte6..7 | 大端 uint16 /10，℃ |
| 速度模式 | 0x7005 | uint8，2；按参数帧低位写入 |
| 速度目标 | 0x700A | float，rad/s |
| 电流限制 | 0x7018 | float，A，电机控制侧相电流限制；不等于直流电源限流 |
| 滤波 Iq | 0x701A | float，A |
| 母线电压 | 0x701C | float，V |
| 速度模式加速度 | 0x7022 | float，rad/s² |
| CAN_TIMEOUT | 0x7028 | uint32，20000=1 s，0=关闭；本工程 5000=250 ms |
| 故障/预警 | 类型 21 | 两个小端 uint32，保留原始位图 |

类型 17 读、18 写：索引 byte0..1 小端，byte2..3 为 0，值 byte4..7 小端；浮点通过 `memcpy` 编解码。类型 3 使能；类型 4 全零停止/失能，byte0=1 为清错请求。版本读取是类型 4、byte1=0xC4，响应复用类型 2，`00 C4 56` 签名后跟版本号；代码单独识别，不将其误作位置。类型 24 用 `01 02 03 04 05 06 01 00` 开启主动反馈，手册说明默认 10 ms。写入均为易失参数，不发送类型 22 保存。

手册物理规格给出额定相电流 2.4 Apk、最大 11 Apk、峰值力矩 5.5 N·m。参数通用表还出现 16 A/14 N·m 等值，与 RS05 物理规格不一致，不能拿来当 RS05 的许可工作限值。工程采用与上位机一致的联调选值：速度上限 33 rad/s（手册第 37 页 `spd_ref 0x700A` 在速度模式下的指令上界）、相电流 11 A（物理最大）、加速度 150 rad/s²（参数表上限）；默认准备值为 33 rad/s / 2.4 A（额定）/ 20 rad/s²（手册默认），见 `App/app_config.h` 与上位机 `server.py` 的 `LIMITS`。
