# 480 MHz 性能配置与实板回归

日期：2026-10-26。对象：`RobStride05_H743` FreeRTOS 工程与 `上位机/RobStrideConsole.exe`。本次未修改 HAL 兄弟工程。

## 配置依据与最终参数

通过 SWD 读取 `DBGMCU_IDCODE=0x20036450`，确认 STM32H743 Rev.V（修订号 `0x2003`）。采用 ST 数据手册 DS12110 Rev.7 的 Rev.V 限值：LDO、VOS0 下 CPU 最大 480 MHz、AHB 最大 240 MHz、APB 最大 120 MHz。参见该文档第 21 页、表 122（第 215 页）和表 147（第 240 页）。480 MHz 运行条件包括结温不超过 105°C；这不是板卡长期温升实测结论。

| 项目 | 原配置 | 当前配置 |
|---|---:|---:|
| CPU / SystemCoreClock | 200 MHz | 480 MHz |
| AHB / HCLK | 100 MHz | 240 MHz |
| APB1/2/3/4 | 50 MHz | 120 MHz |
| 电源模式 | VOS1 | LDO / VOS0 |
| HSE / PLL1M | 25 MHz / 5 | 25 MHz / 5 |
| PLL1N / VCO | 160 / 800 MHz | 192 / 960 MHz |
| PLL1P / PLL1Q | 4 / 10 | 2 / 12 |
| FDCAN 内核 / 总线 | 80 MHz / 1 Mbps | 80 MHz / 1 Mbps |
| OLED I2C2 内核 | HSI 64 MHz | HSI 64 MHz |
| TIM2 计时 / TIM6 HAL tick | 1 MHz / 1 kHz | 1 MHz / 1 kHz |
| FreeRTOS SysTick | 1 kHz | 1 kHz |
| TIM3 WS2812 PWM | 800 kHz | 800 kHz |
| Flash 等待周期 | 1 | 4 |
| ICache / DCache | 关闭 / 关闭 | 关闭 / 关闭 |

仅提升本芯片在现有供电条件下允许的系统/总线时钟；保留原来已经启用的 FPU。没有为提高主频而打开缓存、修改应用控制周期、提升 CAN 速率或启用未使用的外设。

## 修改位置与维护

- `Core/Src/main.c`：Rev.V 检查、LDO/VOS1→VOS0、PLL1 参数、Flash latency。其它修订芯片会进入错误处理，不会套用 480 MHz。
- `Tools/cubemx_baseline/Core/Src/main.c`：同步启动配置；CubeMX 再生成后执行 `Tools/integrate.py` 恢复已验证的启动/RTOS 集成。
- `RobStride05_H743.ioc`：同步系统时钟、PLL 和供电等级。
- `MDK-ARM/RobStride05_H743.uvprojx` / `Tools/integrate.py`：工程 CPU 与调试器 CLKADS 元数据同步为 480 MHz。连续执行两次集成后，45 个相关源文件和工程文件内容保持一致。
- `BSP/bsp_ws2812.c`：按实际定时器时钟计算 PWM 周期和高电平，不再硬编码 100 MHz。当前 TIM3 为 240 MHz，`PSC=0 / ARR=299`，0/1 高电平分别为 77/204 个 tick（约 321/850 ns）。16 颗数据加复位尾部共 708 个半字，仍位于 DMA 可访问的 D2 SRAM1 `UNINIT` 区。
- `Tools/build.ps1`：默认从 PATH 使用 Python，允许 `-Python` 指定路径；不依赖本机 Codex 的 Python 安装位置。
- `Tools/verify_clocks.py`：从当前 AXF 解析 RAM 符号，核对完整 Flash、寄存器、实际时间推进、两台状态和外设计数。执行前需断开上位机并退出 Keil Debug。

## 本轮实测结果

1. Keil ARMCC 5.06u7 重编译：**0 errors / 0 warnings**。代码 57520、只读数据 1604、读写数据 1296、零初始化数据 38640 字节。
2. Keil 下载：擦除、编程、校验成功，应用正常运行。`boot_stage=9 / fatal=0`；`CCR=0x40200`，两级缓存均未开启。完整 Flash 与当前 AXF 一致。
3. 只读时钟核对全部通过：480/240/120 MHz，VOS0 ready，Flash latency 4；SysTick reload 479999；TIM2 PSC239；TIM6 PSC239/ARR999；TIM3 ARR299；I2C timing `0x10707DBC`；FDCAN 1 Mbps。主机约 1210 ms 内 MCU tick 推进 1206 ms。
4. C 主机检查通过：双电机隔离/命令/反馈、OLED 格式化、灯效命令校验和循环调度。上位机 **28 个 Python 单元测试通过**。
5. 使用本次打包的最终 EXE 进行浏览器实板验证：两台卡片独立编辑、命令门控、首次配置门控均正常，无 JavaScript 异常。
6. 通过正式上位机 API 实测两台各自 ±0.5 rad/s、同时 +2/−2、同时 +5/−5、同时反向 −2/+2、只停第一台而第二台保持 +2、最后两台全部失能。限流 1 A，加速度 5 rad/s²。+5/−5 段稳定尾部均值分别 **+4.998/−4.994 rad/s**；单台停止段两台均值约 **+0.003/+1.953 rad/s**。所有阶段均在测试容差内。
7. 运动中两台位置反馈连续更新且数值有效，范围分别约 −11.15～8.76、−12.10～12.44 rad；速度、电流、电压、温度数据正常更新，无故障。位置为协议反馈，当前仍是速度控制，并未增加位置闭环或多圈展开功能。
8. 最终 EXE 灯带回归通过：7 种效果、RGB、亮度/速度、关灯/恢复、重复列表 `[7,1,7]`、按顺序循环、保存/读取、页面重载与断开后继续执行。16 颗 PWM 数据全部存在，复位低电平尾部完整，DMA/灯带错误计数为 0。本次验证了板上波形数据和运行状态，未使用示波器或光学方式逐颗验光。
9. 实板 OLED 帧缓冲回读可解码，两台 ID `7F/7E`、状态和 RTOS 信息正常，无未知字形。运动后继续运行检查约 30 秒，CAN/OLED/灯带错误为 0，任务心跳、OLED 刷新和灯带帧持续增长。最终两台在线且失能，上位机已断开。
