# 烧写与上板验收

## 0. 前提

- 电机主电源独立供电（48 V 额定、最大 60 V），不由板上 3.3 V/5 V 供电；电机固定在支架、输出无负载、导线不卷入转动件，**电源随手可断**。
- 接线仍按 `Docs/01_硬件与协议.md`，本工程没有改动任何引脚分配：PB9/PB8 = FDCAN1，PB10/PB11 = I²C2，PA6 = WS2812，TIM2 只做计时。
- 探针（Horco CMSIS-DAP）不被 Keil 调试会话或上位机占用。

## 1. 烧写

两种方式等价，都会覆盖整片 Flash 的镜像区：

```powershell
# A. Keil 下载器（推荐，uvoptx 已配好 CMSIS-DAP + STM32H7x_2048.FLM）
& 'C:\Keil_v5\UV4\UV4.exe' -f .\MDK-ARM\RobStride05_H743.uvprojx -j0 -o .\Tools\keil_flash.log

# B. pyocd（需 pyocd + pyelftools；先连 attach 再写，避开本探针不支持的 nRESET 序列）
python .\Tools\flash_and_verify.py            # 写前自动备份到 Tools/backup/
```

期望日志：`Erase Done. Programming Done. Verify OK. Application running ...`

回滚：`Tools/backup/flash_before_*.bin` 是烧写前的 128 KB 现场，用相同的烧写工具按 `0x08000000` 基址写回即可。

## 2. 只读验收（不使能电机）

```powershell
python .\Tools\flash_and_verify.py --no-flash
```

| 检查项 | 通过条件 | 失败看哪里 |
|---|---|---|
| `system.boot_stage` | 9 | 1–8 表示卡在某段启动；6/7 常见于 FDCAN/I²C 初始化 |
| `system.fatal` | 0 | 非 0 查 `App/app_main.h` 的 `APP_FATAL_*`，配合 `cfsr/hfsr/exception` |
| `system.vtor` | `0x08000000` | 否则向量表没指到内部 Flash，调度器不会启动 |
| `system.ccr` | `0x40200`（bit16/17 为 0） | 非 0 说明有人打开了 Cache |
| `loop_heartbeat` / `tick_ms` | 连续两次采样必须增大 | 停止说明调度器或电机任务卡死 |
| `motor.online` / `feedback_age_ms` | online=1、年龄 < 150 ms | 检查 CANH/L、120 Ω 终端、电机供电 |
| `can.rx` / `can.tx_ok` | 都在增长，`bus_off=0`、`rx_drop=0` | `tx_ok` 不增：ACK 不到，查总线与电机是否上电 |
| `oled.ready` / `refresh_ok` | ready=1、refresh_ok 增长、refresh_fail=0 | 缺屏时会退避重试，不影响电机与灯带 |
| `led.ready` / `frames_started` | ready=1、frames_started≈50/秒 | `last_error=2` 表示 Cache 被打开 |

`--no-motor-check` 用于电机未上电时只验证 MCU 侧。

### 屏幕应该显示什么

0.96" OLED 共 8 行 × 21 字符，内容从上到下固定为：

```text
UP 00:00:08 SW 15763      ← 运行时长 + 上电以来上下文切换次数（约 1800-2000/s）
HEAP 16.0K MIN 16.0K      ← 剩余堆 / 历史最小（相等=无泄漏）
MOTOR  BLK 1.2 S1.5K      ← 线程名 状态 CPU占用% 剩余栈
OLED   RUN 1.3 S1.9K
HEALTH BLK 0.0 S0.8K
LED    BLK 0.8 S1.3K
MOT ONLINE  V+0.043       ← 在线才有速度；离线显示 ---
SET +0.000 RAD/S DIS      ← 目标速度 + 应用状态
```

判读规则：

- 第 0 行秒数在走 = 调度器在跑；`SW` 数字每帧跳几百 = 每秒约两千次任务切换；两者都不动 = 卡死或掉电。
- 第 2–5 行第 3 列是**该线程的 CPU 占用百分比**（调度器统计的最近 200 ms 窗口），四者之和 ≈ 100 − IDLE 占用。电机使能、灯带动画时，对应数字会明显变化。
- 状态列 `RUN` = 正在跑（画屏的 OLED 必然是 RUN），`RDY` = 就绪待调度，`BLK` = 在 `osDelayUntil`/等中断里阻塞，属周期任务的正常状态。
- `S` 后面是**剩余栈**（FreeRTOS 高水位）；持续变小说明该任务栈不够。
- 第 6 行 `OFFLINE` / `V  ---` 表示没有新鲜反馈；此时不要相信任何速度读数。
- 第 7 行末尾是应用状态：`DIS` 未准备、`PRE` 已准备、`ENA` 已使能、`RUN` 运行、`STP` 减速停止、`FLT` 故障、`CFG`/`ENG` 命令执行中。

没有屏幕也能核对同一内容：`python Tools/read_oled_page.py` 会从 RAM 读出 `pixels` 帧缓冲，用 `Devices/oled_font.h` 的字形反解成文字，并报告是否有字符缺字形。

## 3. 上位机连接

1. 双击 `上位机\RobStrideConsole.exe`，浏览器打开 <http://127.0.0.1:8765>。
2. 刷新探针 → 选择探针 → 连接。连接会核对**整段 Flash** 与 AXF 是否一致，并在 60 ms 内看到心跳递增才接受。
   - 3.0 版起同时支持 `RobStride05_H743`（FreeRTOS）与 `RobStride05_H743_HAL`（单线程）两个工程，按板上 Flash 自动选择，日志会显示 `Flash 一致 · 工程名`。
3. 页面显示 `ONLINE`、母线电压、位置/速度/温度后才进入控制。

## 4. 首次控制顺序

1. 勾选空载联调确认。
2. 设定速度上限 / 相电流 / 加速度（默认 33 / 2.4 / 20），点「准备」，等待 `executed_seq` 完成且状态变 PREPARED。
3. 目标速度保持 0，点「使能」，等待状态 ENABLED。
4. 设目标速度（先 ±1 rad/s 以内），点「运行」。运行会在 MCU 内保持，直到停止/失能/故障。
5. 先「减速停止」验证斜坡，再「立即失能」。断开或退出前先失能。

`state` 与固件一一对应：0 DISABLED、1 PREPARED、2 ENABLED、3 RUNNING、4 STOPPING、5 FAULT。

## 5. 故障排查

| 现象 | 优先检查 |
|---|---|
| 连接被拒「板上固件与任何工程 AXF 都不一致」 | 板上的固件不是当前两个工程编出来的；重新 F7 + Download |
| 连接被拒「H743 主循环没有递增」 | 停在断点、`fatal` 非 0、或调度器没起来 |
| `boot_stage` 停在 2/3 | HSE 25 MHz 未起振、供电/晶振问题 |
| `fatal=7` | 看 `g_assert_file/g_assert_line`；常见于栈不足或非法 RTOS 调用 |
| `fatal=5/6` | FreeRTOS heap 或任务栈不足（当前 24 KB heap、2/3/1.5/1 KB 栈） |
| `RESULT_SERVICE_GAP` | 调试暂停时间过长；失能后重新准备 |
| `RESULT_OFFLINE` | 反馈年龄 ≥150 ms：CAN 断线、电机掉电、终端电阻 |
| `health_fault=2` | TIM2 被冻结或时基异常，复位后复查 |
| 灯带不亮但 `frames_started` 增长 | 灯带接线/供电/颜色顺序（`g_led.color_order`） |
