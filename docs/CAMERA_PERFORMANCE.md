## 本次修改

- 人体检测默认 OpenCV 线程数为 2，可用 `PERSON_CV_THREADS` 覆盖。此设置只作用于人体检测进程。
- 检测的彩色/深度订阅采用最新一帧队列；回调仅保存消息，推理开始后才解码彩色图，不再每张预览图都解码。
- 检测结果 JSON 保留原有字段，新增 `source_stamp`、`decode_ms`、`input_age_ms`、`result_age_ms`、`color_depth_skew_ms`。识别图与目标位姿保留输入时间戳；不再把处理完成时间当作采集时间。
- 基于整套任务下的 3 次/秒验证，检测默认上限从 2 调整为 3。可用 `PERSON_MAX_FPS` 覆盖；此参数是上限，不保证实际帧率。
- 启动脚本检查已有的人体检测/Orbbec 深度 launch，避免重复运行。未自动杀死其他进程。

例如恢复 2 次/秒上限：

```bash
PERSON_MAX_FPS=2 bash scripts/start_host_stack.sh --viz foxglove --person
```

## 已完成验证及限制

导航、语音、手部检测、深度、Foxglove 同时启动，电机未使能。最新帧替换、避免重复推理、带行填充的 16 位深度解码及源时间戳检查通过。

初始 22 秒采样：本地深度约 29.64 Hz、彩色 9.83 Hz，人体结果约 1.58 Hz；采样包含多个额外诊断订阅，CPU 约 93%–96%。

后续轻量观察只订阅识别结果，保持其余任务运行：原版 2.00 Hz、修复版在同样 2 次/秒上限下为 2.00 Hz，两者推理中位数分别约 144/147 ms；修复版调到 3 次/秒后实测 3.00 Hz，推理中位数约 147 ms、P95 174 ms。不同采样负载下的数值不能直接混成同一组前后提升比例。

独立线程对照的推理中位数为 4 线程 265 ms、1 线程 195 ms、2 线程 130 ms；这支持默认使用 2 线程，但整套任务下不保证每一帧都按相同比例提速。

最终从修改后的一键脚本完整重启，22 秒健康检查得到：彩色 10.07 Hz、人体识别 2.99 Hz、里程计 30.04 Hz、激光扫描 12.03 Hz。前 8 秒单独观察深度为 30.19 Hz、最大帧间隔约 54.7 ms。识别推理中位数 143.8 ms、P95 208.5 ms，结果相对输入的年龄中位数 208 ms。这是静止场景数据，未执行导航路径或实车跟随测试。

本次没有改变相机/导航标定、人体模型、深度分辨率、运动控制参数，也没有改动语音拍照的相机采集实现。语音拍照与预览共用相机句柄的后续修复，以及远程深度预览压缩属于下一阶段。

原始深度若以 320×240、16 位、30 Hz 传输，仅像素负载约 36.9 Mbps/客户端。测试期间观察到多个 Foxglove 连接和其中一个约 2 MB 的发送积压；这不是识别线程优化能够全部解决的问题。本次没有修改用户的 Foxglove 布局或关闭其连接。
